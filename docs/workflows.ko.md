# 실전 활용 가이드

[English](workflows.md) · [문서 목차](guide.ko.md)

예시는 가상의 **Harbor Response Drill** 프로젝트와 **1.2.0** 버전을 사용합니다. 프로젝트에 맞춰 훈련 보고서, 검토한 문서, 데이터셋 등을 산출물로 기록할 수 있습니다.

## 여러 에이전트의 작업 조율

1. 관리자가 프로젝트와 버전을 만듭니다. 작성 세션마다 필요한 프로젝트 권한을 부여하고, 독립 검토자에게 `verify` 권한을 부여합니다.
2. 계획 에이전트가 기대 결과를 명세에 기록합니다. 담당과 성공 조건을 정해 작업을 만들거나 기존 작업을 연결합니다. 참여 세션이 같은 프로젝트와 버전을 사용합니다.
3. 작업 에이전트는 수정 전에 현재 기록과 행 버전을 조회합니다. 관찰 내용을 기존 이슈에 추가하고, 새로운 문제라면 이슈를 등록합니다. 여러 기록이 함께 저장돼야 할 때는 `ledger_batch`를 사용합니다.
4. 관리자는 개요의 조치 목록과 버전 필터로 담당 없는 이슈, 차단된 작업, 검증을 기다리는 완료 보고를 확인합니다.

## 완료 보고와 독립 검증

1. 작업 에이전트는 어떤 결과물을 만들었고 어디서 근거를 확인할 수 있는지 기록합니다. 관련 항목에서 완료를 보고합니다.
2. 검토자는 항목, 산출물, 관련 이력을 읽습니다. 해당 항목의 독립성 요건을 확인한 뒤 `evidence_uri`를 포함해 `ledger_review`를 호출합니다. 세부 자격 조건은 [장부 개념](concepts.ko.md#개념)을 참조합니다.
3. 근거가 부족하면 이유를 기록하고 현재 담당자에게 후속 작업을 요청합니다. 이미 검증한 항목을 수정하려면 검토자가 먼저 다시 엽니다. 기존 판정은 이력에 보존됩니다.

## 출시 결정

1. 출시 기준을 마일스톤에 모읍니다. 기준마다 평가에 필요한 작업·명세·이슈를 연결합니다.
2. 대상 버전의 완료 근거를 남깁니다. 독립 검토자가 기준을 평가해 근거와 함께 `MET` 또는 `NOT_MET`을 기록합니다.
3. 버전 개요와 출시 기준을 함께 살펴봅니다. 각 판정과 미해결 이슈, 차단된 작업을 확인하고 Go/No-Go 판단 근거를 관련 장부 기록에 남깁니다. 계획이 취소되면 마일스톤을 보관합니다.

설치와 세션 연결은 [에이전트 연동 가이드](client-hooks.ko.md), 도구별 한도와 입력은 [MCP 레퍼런스](mcp.ko.md)를 참조합니다.
